**T34 — Capture rapide et saisie rapide** · Dépendances : T06, T24, T25.
- Origine : les liens enregistrés dans un carnet se perdaient, sans date ni contexte ; la saisie répétitive d'une vente quotidienne doit tenir en un ou deux gestes. Si garder une information est lent, l'utilisateur retourne à son carnet.
- Capture depuis l'extérieur : Android via la cible de partage du système ; web via une application installable ou un marque-page ; ordinateur via le presse-papiers ; iOS via l'extension de partage si Flutter le permet, sinon documenter la limite. L'élément partagé (lien, texte, image, fichier) devient une entrée dans une collection et un format de données par défaut, avec date de création, champ de note pour le contexte et source si disponible.
- Le lien est enregistré tel quel. Ne pas télécharger la page ni générer d'aperçu sans choix explicite de l'utilisateur et sans définir permissions et provenance (T25).
- Collection de capture par défaut modifiable ; choix en un geste lorsqu'il y en a plusieurs.
- Dédoublonnage de liens : avertir et proposer d'ouvrir l'entrée existante ou d'ajouter quand même ; jamais de fusion silencieuse.
- Saisie rapide : un « modèle de saisie » par format de données avec valeurs par défaut, champs repliés, date du jour automatique, action « Dupliquer la dernière entrée » et suggestions de valeurs fréquentes calculées dans le compte de l'utilisateur.
- Si le hors ligne n'est pas disponible (T29), afficher une erreur claire plutôt que de perdre le contenu partagé.
- Architecture modulaire : isoler l'interface de capture/saisie rapide dans des composants dédiés (`quick-capture-dialog.tsx` sur web, `lib/quick_capture_sheet.dart` sur Flutter) sans alourdir `workspace_screen.dart`.
- **Terminé quand :** depuis un navigateur sur téléphone, un lien est enregistré avec une note en trois gestes ou moins ; sa date de création et sa note apparaissent dans la liste et une recherche le retrouve par un mot de la note ; un lien déjà présent est signalé ; une vente (date du jour, quantité habituelle, montant) s'enregistre en deux gestes ou moins après configuration ; un échec réseau ne perd pas le contenu partagé ; tests sur Android, web et ordinateur, limite iOS documentée. Scénarios R1 et R2.
