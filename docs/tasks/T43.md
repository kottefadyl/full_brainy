- Niveau par champ et par format de données : ordinaire, personnel ou sensible, choisi par l'utilisateur (les modèles de santé et de position proposent « sensible »). Les champs sensibles sont exclus par défaut des partages et des exports, avec inclusion explicite possible, et masqués dans les vues partagées (ajustement A7).
- **Seuil minimal d'effectif** configurable avant d'afficher un agrégat sur des données sensibles, appliqué par l'API (règle 16). Prendre en compte les recoupements évidents (différence entre deux agrégats, groupes complémentaires) ; documenter les limites et les tester. Ne jamais présenter cela comme de l'anonymisation.
- Journaliser les accès et partages sensibles (T28).
- **Terminé quand :** un groupe sous le seuil n'est pas retourné même si le client est contourné ; un partage ou un export n'inclut pas un champ sensible sans choix explicite ; un test de recoupement simple est bloqué ou signalé ; les textes EN/FR expliquent les limites. Scénarios R7 et R8.

## Livraison

- L'API applique les niveaux effectifs et le seuil configurable (2–100, initialement 5), masque les valeurs protégées dans les lectures partagées et refuse filtres, comparaisons et sources détaillées pour les analyses sensibles.
- Les exports de collection excluent les champs protégés par défaut sur web et Flutter ; les sauvegardes complètes et les exports géographiques demandent une inclusion explicite. Les partages consignent les champs accordés sans recopier leurs valeurs dans l'audit.
- Le contrat et les limites sont décrits dans [T43_CONFIDENTIALITE.md](../T43_CONFIDENTIALITE.md). Les scénarios R7/R8 sont vérifiés par `api/scripts/sensitivity-smoke.mjs`.
