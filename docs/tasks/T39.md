## Arborescences profondes et sélecteur — 8 novembre 2026

**API.** Hiérarchie portée à 8 niveaux, analysée en un seul passage (`codeHierarchy`) : cycle, parent absent et dépassement sont distingués et signalés ligne par ligne en CSV. Un paquet de domaine cyclique est refusé dès l'aperçu. Nouvelle requête `classificationCodePaths`.

**Web et Flutter.** Le champ code et le choix du parent utilisent un sélecteur à recherche instantanée, insensible à la casse et aux accents, sur le libellé et le code, avec fil d'Ariane sur les résultats et arbre dépliable. Un code obsolète n'est plus proposé mais reste lisible sur l'entrée qui le porte ; un parent ne peut pas être choisi parmi ses descendants. L'éditeur de liste propose de parcourir l'arborescence et signale un dépassement avant l'enregistrement. Le niveau de regroupement des analyses suit la profondeur réelle de la liste.

**Recette.** API : typecheck, fumées classification, paquets de domaine (nomenclature à 5 niveaux installée, assignée et regroupée ; paquet cyclique refusé) et collections. Web : lint, TypeScript et build ; Chrome réel, 12 configurations (320, 390, 1280 ; clair/sombre ; FR/EN) avec `scripts/visual/phase-two-b/code-picker.mjs`, bancs `check.mjs` et `date-focus.mjs` rejoués ; parcours connecté réel à 1280 px sur l'API locale (saisie d'une entrée au code profond, éditeur de liste, refus d'un neuvième niveau et d'un cycle), comptes temporaires supprimés. Flutter : analyse sans problème, 104 tests réussis, rendu natif Windows contrôlé en thème sombre à 320 px ; le correctif de largeur de la colonne de code, postérieur à cette capture, est couvert par un test de widget.

**Limites.** Une liste reste plafonnée à 5 000 codes (levé le 10 novembre, voir ci-dessous). L'arbre web affiche 300 lignes au plus, puis invite à chercher. L'éditeur affiche toujours une ligne par code, lourde sur une très longue liste. Le pliage d'accents de Flutter couvre les alphabets latins courants. Aucune construction iOS, macOS ou Linux depuis ce poste Windows (le sélecteur n'utilise aucun code propre à une plateforme), aucun téléphone physique, aucun lecteur d'écran réel.

**Flutter mobile et ordinateur.** Le même sélecteur sert les deux : feuille inférieure sur écran étroit, dialogue sur grand écran. Sur ordinateur, la recherche prend le focus et les flèches, Entrée et Échap fonctionnent comme sur le web ; sur mobile, le clavier ne recouvre pas l'arbre à l'ouverture. Rendu natif réel contrôlé sur Windows et émulateur Android (Pixel 8), clair et sombre ; application complète construite pour Windows et Android ; 107 tests réussis.


## Référentiels et grandes listes (T39/1, T39/3) — 10 novembre 2026

**API** (`e20d9f9`). `previewReferential` et `importReferential` lisent un CSV (virgules ou points-virgules, colonnes `code`, `label` ou `label_en`/`label_fr`, `parent_code` facultatif) ou un JSON plat ou imbriqué (`children`), avec erreurs ligne par ligne avant toute écriture. Au-delà de 5 000 codes, et jusqu'à 50 000 sur 8 niveaux, la liste est stockée à part, versionnée et marquée `external` : la collection n'envoie plus ses codes, seulement `codeCount` et `levels`. `searchClassificationCodes` rend au plus 50 codes (recherche sans accents ou enfants d'un parent, avec chemin) et `classificationCodesByValue` étiquette les codes déjà saisis. Entrées, regroupement par niveau, libellés et sauvegardes les prennent en charge ; copie, fusion, édition code par code et paquets de domaine les refusent explicitement. Un nouvel import remplace la liste à condition de conserver chaque code existant.

**Web** (`b71f239`, banc `91d68ff`). Le sélecteur de code et l'écran des listes basculent sur un navigateur distant (niveau par niveau, → et ←, recherche différée de 250 ms) ; un panneau d'import propose le nom à partir du fichier, affiche l'aperçu et bloque l'import en cas d'erreur.

**Flutter** (`a75c242`). Mêmes comportements : `referentials_api.dart`, `remote_code_browser.dart` et `referential_import.dart` ; `CodePickerField` reçoit une source distante dans l'éditeur d'entrée et l'écran des classifications ; les analyses lisent `levels`.

**Recette.** API : typecheck, fumées `smoke:referentials` (import de 6 000 codes, recherche, parcours, entrées, regroupement, remplacement, refus, JSON imbriqué, sauvegarde) et `smoke:collections`. Web : lint, TypeScript ; banc Chrome `scripts/visual/phase-two-b/remote-codes.mjs` sur 12 configurations (320, 390, 1280 ; clair/sombre ; FR/EN) avec API simulée. Flutter : analyse sans problème, 156 tests réussis dont 8 nouveaux (`test/remote_codes_test.dart`). Les requêtes Flutter sont validées contre `api/schema.gql`.

**Rendu natif Flutter (10 novembre).** `brainy/tool/large_codes_preview.dart` parcourt, sur l'API locale réelle et un compte temporaire, l'écran des classifications (ouvert sur la liste par `initialListId`) et le sélecteur : 6 000 codes portés par un simple compte, libellé du code enregistré, ouverture d'un niveau, recherche sans accents, choix ; Windows 320 et 1000 px, clair et sombre, 21 contrôles réussis.

**Limites.** Rendu Android d'une grande liste non vérifié ; les codes d'une grande liste suivent l'ordre naturel (« Région 2 » avant « Région 10 », API `collation numericOrdering`) tandis qu'une liste locale garde l'ordre saisi ; aucun lecteur d'écran réel. Une grande liste ne se modifie que par un nouvel import. La copie d'une entrée affiche le code seul, sans libellé, pour une grande liste. Un fichier est limité à 4 Mo (limite de requête Vercel).
