**T54 — Champ « Collaborateur » (personnes d'une entrée)** · Dépendances : T52 (collaborateurs), T53 (résumé de personne).
- Demande produit (12 novembre 2026) : un format de données peut avoir un champ dont la valeur est une ou plusieurs personnes, par exemple une tâche avec date, intitulé, pourcentage, durée et « Effectuée par » : Kevin, Ivan, Julien. Les personnes proposées sont les collaborateurs de la personne qui a créé le format de données, c'est-à-dire du propriétaire de la collection.
- Décisions : nouveau type `COLLABORATOR` (« Collaborateur » / « Collaborator ») ; choix multiple sans réglage (1 à 20 personnes) ; personnes permises = propriétaire de la collection (proposé en premier) + ses collaborateurs ; un collaborateur en lecture et écriture choisit dans la même liste (il voit donc les noms des collaborateurs du propriétaire, jamais leurs adresses e-mail) ; la valeur garde les identifiants (`personIds`) et les noms au moment de l'enregistrement (`personNames`), et son texte lisible est « Kevin, Ivan, Julien », de sorte que liste, fiche, copie, recherche et tableur fonctionnent sans changement ; une personne dont la collaboration a pris fin reste sur les entrées déjà enregistrées (retirable, plus sélectionnable) ; un client qui renvoie le texte enregistré inchangé garde les mêmes personnes.
- **Terminé quand :** l'API refuse toute personne hors du propriétaire et de ses collaborateurs ; web et Flutter proposent le type dans l'éditeur de formats et un sélecteur de personnes (photo ou initiale, nom, « propriétaire ») dans l'éditeur d'entrée, EN/FR, clair et sombre.

Implémentation : API `FieldKind.COLLABORATOR`, `EntryValue.personIds`/`personNames`, `api/src/collaborators/person-field.service.ts` (`people`, `bind` appelé au début de `validateReferences` : création, modification, import) et `person-field.resolver.ts` (requête `collectionPeople(collectionId)`, réservée au propriétaire et aux membres). Web : `app/person-field-input.tsx` (+ `.css`), branché dans l'éditeur d'entrée de `brainy-app.tsx` ; `Avatar` exporté de `entry-authors.tsx` ; `lib/graphql-types.ts` régénéré. Flutter : `lib/person_field_input.dart`, `BrainyFieldKind.collaborator`, `BrainyEntry.people`, `CollectionsApi.collectionPeople`, `PersonAvatar` (ex-`_Avatar`) dans `entry_authors.dart`, branchement de 3 lignes dans `workspace_screen.dart`.

Validé le 2026-11-12 : `npm run typecheck` ; `smoke:person-field` (liste ordonnée, refus à un inconnu, trois personnes, refus hors collaboration, doublon, liste vide, texte libre, renvoi du texte inchangé, choix par un collaborateur en écriture, fin de collaboration) ; `smoke:collaborators`, `smoke:collections` ; web `lint`, `tsc`, `build` et parcours Edge réel (éditeur d'entrée à 1280 px clair FR et 390 px sombre EN, aucune erreur console) ; `flutter analyze`, 3 tests `person_field_test.dart` et suite Flutter complète (261 tests).
